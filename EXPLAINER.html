Impacto

O que cada mudança significa para quem usa o deep-orchestrator:

Busca Brave integrada — sub-agentes pesquisam na web direto do terminal (curl + API Brave), sem depender de outras ferramentas.
Créditos sob controle — o orquestrador consulta os créditos restantes da API antes de disparar ondas longas.
Execução confiável — contratos ECC (execução de código confiável) que os sub-agentes seguem ao executar código.
Busca padronizada — prompts de pesquisa consistentes entre sub-agentes (search-prompts.md).
De-para visível — toda execução termina com um EXPLAINER.html legível (este documento).
Processo documentado — ondas ilimitadas e o novo fluxo registrados no SKILL.md.

Premissas inferidas sem perguntar

O orquestrador opera em autonomia total: nenhuma pergunta foi feita ao usuário. Toda premissa assumida fica registrada aqui — para revisão e reprodutibilidade.

  • P1. Mobile = navegador móvel apontando para servidor local. Bind 127.0.0.1 NÃO alterado (regra de segurança).
  • P2. Escopo: web/**, sem mudanças em server/**, sem novas rotas.
  • P3. Breakpoints 768/1280. Tablet decide por orientação. Ponteiro grosseiro detectado separado da largura.
  • P4. Contratos congelados: mudanças só aditivas. state/store.ts não tocado.
  • P5. Nenhuma dependência npm nova. Medições em navegador usam ws já instalado.
  • P6. Densidade do grafo entra por prop (nunca useViewport) — o render de servidor devolve desktop.
  • P7. Componente sheet do catálogo NÃO usado (touchAction:none quebra scroll). Backdrop + FocusTrap + ScrollLock mantidos.
  • P8. Arraste vence toque longo (250ms < 500ms). Menu de nó arrastável usa botão "⋯".
  • P9. iOS Safari: sem evento contextmenu. Callout nativo morre por CSS (longpress-menu utility).
  • P10. Paleta de comandos re-ativada (removida em julho). Wrapper sobre motion-ui — sem editar catálogo.

Linha do tempo da execução

As quatro fases do orquestrador e o que aconteceu em cada uma.

  1. Fase 0DELIMITAR

    MODE=normal, BASE_DIR=/home/ondokai/Projects/GitCraque, BASE_BRANCH=main. 0 worktrees de terceiros.

  2. Fase 1ANALYZE

    12 problemas mapeados: layout 3-colunas, sem breakpoints, alvos pequenos, dependência de hover, sem toque longo, DnD sequestra scroll, campos com zoom, grafo 5 colunas, diálogos centralizados, safe-area ignorada, atalhos sem equivalente tocável.

  3. Fase 2PLAN

    3 ondas, 15 sub-agentes. Onda 1: fundação (viewport, i18n). Onda 2A: primitivos de toque. Onda 2B: 7 agentes paralelos. Onda 3: swipe, auditoria, keyboard parity. REPLAN após cada onda.

  4. Fase 3ONDA 1

    4 agentes. useViewport (useSyncExternalStore + rAF), tokens safe-area, dvh, catálogo i18n 52×4, 102 testes.

  5. Fase 3ONDA 2A

    3 agentes. useLongPress (máquina de estados de módulo), useLayoutMode, variante touch CSS, alvos 44px, bottom sheet. Revisão adversarial: 7 perguntas, 0 bloqueadores. 106 testes.

  6. Fase 3ONDA 2B

    7 agentes paralelos. Grafo 5→3 colunas, sensor por atraso, 14 diálogos bottom sheet, diff/markdown estreitos, toolbar compacta, painéis long press, MobileNav + coluna única. Gate: 718 testes.

  7. Fase 3ONDA 3

    3 agentes. Swipe horizontal entre painéis, auditoria de alvos de toque (npm run test:touch), portas tocáveis para Esc e ⌘K.

  8. Fase 4COMMIT-FINAL

    AGENTS.md atualizado (718 testes), EXPLAINER.html gerado, 15 squash commits, zero worktrees remanescentes, contenção provada.
