De-Para: o que mudou

Comparação lado a lado entre o estado inicial do repositório e o estado final após a execução.

Antes
  • Drag-and-drop touch de commits/branches não funcionava: o PointerSensor ativava aos 250ms, mas o navegador roubava o gesto (pointercancel ~11px) e o arraste morria — em device real também.
  • O helper de teste touchDrag movia o dedo dentro dos 250ms de repouso — cancelado pelo sensor (gesto ao contrário).
  • Nenhum teste de UI existia para as 4 operações de git (pull/merge/rebase/cherry-pick) — só o e2e de API (39 checks).
  • O spec de push touch não provava transferência: o reset do remoto rodava depois do commit, e o push do app virava no-op.
  • Docs diziam "um PointerSensor" e "não acrescente touch-action: none" — contradiziam a correção.
Depois
  • TouchSensor para ponteiro coarse: segurar 250ms arrasta; swipe rápido rola a lista. Drag touch real funcionando (provado por probe 4/4 + specs).
  • touchDrag com repouso de 300ms — o gesto do sensor de verdade.
  • 17 specs de UI (8 mouse + 9 touch) cobrindo pull, merge, rebase, cherry-pick e push — com asserção dupla (git CLI real + UI) — contra o repo real no GitHub.
  • Push touch com pré-assertion: o remoto NÃO tem o commit antes do push do app — transferência provada.
  • Docs sincronizados: ESTADO-TOUCH-MOBILE, skill resolving-drag-intents, mapa de fluxos, docstring do harness.

Premissas inferidas sem perguntar

O orquestrador opera em autonomia total — nenhuma pergunta é feita ao usuário. Toda premissa assumida fica registrada aqui — para revisão e reprodutibilidade.

  • Repo de exemplo privado (gitcraque-teste-operacoes em frederico-kluser) — conservadorismo; publicar depois é trivial.
  • Playwright como devDependency do workspace web — o harness vira artefato do produto, fora de npm test (convenção do repo).
  • Cherry-pick touch re-planejado na Onda 2 e revogado na Onda 3: o caminho real de drag ficou testável após o fix do TouchSensor — a história reflete a evolução da verdade.
  • Não testar squash/rebase-interativo e push --force: diálogos sem caller (código morto) e force sem hold destrutivo (defeito conhecido) — vão ao relatório como achados.
  • Gates sequenciais com os projetos de specs (rede compartilhada — pushs concorrentes são rejeitados pelo GitHub).
  • Perf flake tratado 5x como ruído ambiental com prova (re-run isolado verde + diff que não toca web/src/graph).
  • Subwaves 2/3 absorvidas pelos gates das ondas + gate final (decisão de processo documentada).
